API

The public API other systems call, at /api/v1.

Authentication

Every call sends Authorization: Bearer <token>. Any user creates tokens on the API tokens page of the web app, and a call made with one acts as the user who created it. The token is shown once, when it is created; only its SHA-256 hash is stored, in api_tokens.

A token is pat_ followed by 32 random bytes, base64url: 47 characters in all. Every user sees every token and can revoke any of them; a revoked token stops working on the next call.

Refused calls

WhenResponse
No Authorization header, or not Bearer401 with WWW-Authenticate: Bearer. The body is the same in every case, so a caller can't tell an unknown token from a revoked one.

Files

The files in a workspace, read and changed one at a time. A path is relative to the workspace root, like src/app.ts; in the URL it comes after /files/.

A path that leads outside the workspace, with .. or through a link, is answered as if it doesn't exist. Every route here also answers 401 as described in Authentication.

Ignored folders

The tree never lists these folders, so a listing stays small: node_modules, .git, dist, .next, .turbo, coverage. Their files can still be read and changed by path.

Text and binary

Read and edit work on text. A file with a NUL byte in its first 8 KB is binary, and is refused with 400.

Sizes

A read without limit is refused with 400 when the file is over 512 KB; read it in parts instead. A line over 2,000 characters is cut there and ends in … [truncated]. A write whose body is over 1 MB is refused with 413.

Sandbox

Commands that run inside a workspace, on its files. Exec runs a command to the end and returns its output. Launch starts a long-running process in the background and exposes one of its ports at a public URL. A workspace runs one background process at a time, and its status is running while it does; exec can run alongside it. A background process with no traffic for 15 minutes is stopped, and the next request to its URL starts it again with the same launch. Stop ends that: the URL stops answering until the next launch.

A command is run with sh -c from the workspace root. Every route here also answers 401 as described in Authentication.

Network

By default a command can reach every public host. Launch's network changes that for the background process and every exec that runs alongside it, with two lists: deny blocks hosts, and allow opens hosts again that deny blocked. A host is a name, like registry.npmjs.org, or a pattern: *.npmjs.org matches any name ending in .npmjs.org, and * matches every host. So {"deny": ["*"], "allow": ["registry.npmjs.org"]} reaches only the npm registry.

Commands reach the internet through a proxy at 127.0.0.1:3128, set in HTTP_PROXY, HTTPS_PROXY and their lowercase forms. npm, curl, git, pip, Bun and Node with NODE_USE_ENV_PROXY (also set) all use it. A tool that ignores these settings can't reach the internet. Private addresses are never reachable, whatever the lists say.
