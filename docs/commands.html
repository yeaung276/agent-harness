Commands

Commands run with bun run from the root of a checkout. ca:create writes harness/.env; migrate:harness reads it, as the server does; user:create reads DATABASE_URL from its environment. They talk to Postgres directly.

Authentication

There is no register page. A user exists only after user:create adds them, and logs in on the web with that email and password. Passwords can't be changed for now.

user:create

DATABASE_URL=postgres://… bun run user:create <email>
StepWhat happens
EmailTrimmed and lowercased. Not an email address → exit 1.
PasswordAsked twice, without echo. From a pipe, the first line of stdin, asked once. Fewer than 8 characters, or the two don't match → exit 1.
SaveHashed with argon2id and inserted into users. The email is already there → exit 1, nothing changes.
DonePrints the new user's id → exit 0.

Database

Migrations are SQL files in harness/drizzle/, committed with the code. bun run db:generate in harness/ writes a new one from the changes in src/db/schema.ts. The server never migrates; run migrate:harness by hand before starting a version with new migrations.

migrate:harness

bun run migrate:harness
StepWhat happens
ReadThe migrations in drizzle/, and the last one applied, from drizzle.__drizzle_migrations.
ApplyEvery newer one, in order, in one transaction, each recorded in drizzle.__drizzle_migrations. One fails → all roll back, exit 1.
DoneExit 0. Nothing newer → nothing changes.

Workers

ca:create

bun run ca:create
StepWhat happens
Join secretharness/.env has no WORKER_JOIN_SECRET → adds 32 random bytes, hex.
CAharness/.env has neither WORKER_CA_KEY nor WORKER_CA_CERT → makes a P-256 key and a self-signed certificate, CN worker-ca, valid 10 years, with openssl, and adds both.
DonePrints the names it wrote. All three are there → prints that nothing was written, and the file is unchanged.

Development

CommandWhat it does
bun run dev:harnessThe server on http://localhost:3000, restarting on changes, and the CSS build. With APP_MODE=worker and NODE_ENV=development, a worker that skips registration and serves plain HTTP.
bun run --filter harness testThe unit tests; those that need bubblewrap are skipped.
bun run test:harnessEvery test, inside a privileged Linux container.
bun run formatPrettier on every .ts file.
bun run docsThese docs on http://127.0.0.1:8000.
bun installAlso sets core.hooksPath to .githooks. Its pre-commit hook formats the staged .ts files, stages them again, and runs the unit tests; a failing test stops the commit.
